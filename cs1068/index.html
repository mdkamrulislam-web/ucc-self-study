Lesson 1Lectures 0.2 and 1.1

From problem to program

The one ideaPython comes last. First you pin down the problem, then you write the steps (the algorithm) in plain words or a flowchart, and only then do you translate those steps into code and test it.

The four steps

Lecture 1.1 calls these the four pillars of programming, and Quiz 2 asked for them in order:

  1. Identify the problem. What exactly should happen? What goes in, what comes out?
  2. Design a solution. Write the algorithm: a finite sequence of well-defined steps. Use pseudocode or a flowchart.
  3. Write the program. Translate each step into Python.
  4. Check the solution. Run it with different inputs and fix what is wrong.

A program is “a set of instructions written in a programming language that tells a computer what to do” (the exact wording Quiz 2 used). Writing those instructions is called programming or coding. Application programs help users (Google Maps, Word, games); system programs run the computer itself (drivers, Windows, Linux).

The lecturer’s worked example: an average

Problem: a teacher wants a student’s average from two test scores. Algorithm, “a structured method for a computer to solve a problem step by step”, split into input, processing and output. Lecture 1.1 then writes it two ways. Pseudocode is symbolic text that must be translated into a programming language before it can run; it lets you write out the logic without worrying about code. A flowchart is a diagram of the same algorithm, read from top to bottom, with shapes for the steps and arrows between them.

Pseudocode

Program find_average
  Input num1
  Input num2
  Sum = num1 + num2
  Average = Sum / 2
  Print Average

Flowchart

Flowchart shapes: rounded box for start and end, parallelogram for input and output, rectangle for a processing step, and (from Lesson 10) a diamond for a yes/no decision. Arrows run top to bottom.

Only now do we write Python. Each pseudocode line becomes one line of code (Lecture 1.2, slide 2):

score1 = 80
score2 = 90
average = (score1 + score2) / 2
print("Average score:", average)
Average score: 85.0

Notice the brackets: without them Python would compute score1 + score2 / 2 = 80 + 45 = 125. Lesson 5 explains why.

An algorithm that won a Nobel Prize

Lecture 0.2 showed that an algorithm is an idea, not code. In 1962 Gale and Shapley gave a step-by-step procedure for the stable marriage problem: n people on each side rank everyone on the other side, and we want a matching with no blocking pair (two people who both prefer each other to their current partners).

Each day, until everyone is engaged:
  Morning:   every unengaged proposer proposes to the top person
             on their list they haven't proposed to yet
  Afternoon: every receiver keeps the best proposal so far
             and rejects the rest
  Evening:   every rejected proposer crosses that name off their list

(The slide’s termination line reads “repeat days until any person is engaged”; it means until every person is engaged.)

Worked example · Lecture 0.2, slide 15

Four boys and four girls, each with a ranked list, favourite first:

BoyRanking, 1st to 4th
JimAmy, Dee, Cathy, Beth
KenAmy, Beth, Cathy, Dee

GirlRanking, 1st to 4th

Boys propose. Follow the three steps day by day:

DayProposalsDecisions
1Jim → Amy, Ken → Amy, Leo → Beth, Max → CathyAmy keeps Jim (she ranks him above Ken). Beth holds Leo, Cathy holds Max.
2Ken → BethBeth prefers Leo: Ken rejected again.
3Ken → CathyCathy prefers Ken to Max: she swaps, Max is free.
4Max → AmyAmy prefers Jim: Max rejected.
5Max → BethBeth prefers Max to Leo: she swaps, Leo is free.
6Leo → DeeDee is free and accepts. Everyone is engaged.

Result: (Jim, Amy) (Max, Beth) (Ken, Cathy) (Leo, Dee), the slide’s answer. Girls propose instead and every girl’s first choice is a different boy, so it ends on day 1 with (Amy, Leo) (Beth, Jim) (Cathy, Ken) (Dee, Max). Both matchings are stable, yet they differ: the side that proposes ends up with the best partners it can have in any stable matching.

The procedure always ends, and always ends with a stable matching. Versions of it run school admissions in New York (unmatched students fell from about 30,000 to 3,000 a year), kidney exchanges, and the assignment of users to web servers. Shapley and Roth shared the 2012 Nobel Prize in Economics for this work.

Lecture 0.2’s exercise: boys A: X Y Z, B: X Z Y, C: Y X Z; girls X: B A C, Y: A C B, Z: C B A. Find a stable matching.

Boys propose. Day 1: A and B propose to X, C to Y; X keeps B. Day 2: A → Y, and Y prefers A to C, so C is free. Day 3: C → X, who keeps B. Day 4: C → Z, who accepts. Result: (A, Y) (B, X) (C, Z).

With the girls proposing, X → B, Y → A and Z → C all accept on day 1: the same matching. When both versions agree, that matching is the only stable one.

print is a function: a named block of code that does a job. You call it by writing its name followed by brackets, with what it needs inside. The text in quotes is a string. Single or double quotes both work, as long as they match.

Syntax matters

Python is fussy. Each of these is a different mistake (Quiz 3 Q8 was exactly this):

LineWhat Python does

Three kinds of error

Past papers ask you to find errors “both syntactic and logical”. It helps to know the three kinds:

KindWhen you find outExample
Syntax errorBefore anything runs: Python can’t read the file, so not even line 1 runs.print Welcome, a missing colon or bracket, bad indentation (SyntaxError, IndentationError)
Runtime errorWhile it runs: the program stops at the bad line, after earlier lines have already run.print(Welcome) (NameError), 1 + "3" (TypeError), int("2.5") (ValueError)
Logic errorNever, unless you test: it runs and prints an answer, but the answer is wrong.score1 + score2 / 2 without brackets gives 125 instead of 85

Python reports the first two for you. Only testing (step 4) catches the third, which is why the lecturer insists on it.

Comments

A comment is text Python ignores, written for people. “All professional code should be commented” (Lecture 1.1).

  • ''' … ''' (or """ … """) wraps several lines. Lesson 15 uses this for a function’s docstring.

The one ideaA variable is a name stuck onto a value in memory. = does not mean “equals”: it means “work out the right-hand side, then stick the left-hand name on the result”. Reading a name that was never assigned is an error.

The variable is on the left, the value on the right, and = is the assignment operator (slide 5). Later lines can use the name instead of the value: sum = score1 + score2.

Variables can change

Slide 16 spells out what x = 2 * 3 does:

  1. Evaluate the expression on the right (2 * 3 → 6).
  2. Attach the name on the left to the result.
  3. Detach any old value from that name.
x = 10       # x is 10
x = 2 * 3    # x is now 6
print(x)
x = x + 1    # right side first: 6 + 1 = 7, then x is 7
print(x)

7

x = x + 1 would be nonsense in maths, but it is perfectly normal Python: the right side is finished before the left side is touched.

Process

      
Identify the problem → design (pseudocode, flowchart) → write → check. Input → processing → output.

      
Flowchart: oval start/end, parallelogram input/output, rectangle process, diamond decision.

    

    
Variables

      
name = value: right side first, then attach the name. Names: letters, digits, _; not starting with a digit; no spaces; not a keyword; case-sensitive. Style: snake_case.

      
Unassigned name → NameError.

    

    
Types

      
int 10 · float 10.0 · str "10" · bool True/False. type(x) → <class 'int'>.

      
Containers to come: list [1, 2], tuple (1, 2), dict {'a': 1}.

    

    
Operators

      
/ float always (36/4 → 9.0) · // floor · % remainder · ** power.

      
Order: ( ) → ** → * / // % → + -, left to right. Strings: + joins, * n repeats; int + str → TypeError.

    

    
Casting

      
int(2.999) → 2 (chops) · int("7") → 7 · int("2.5") → ValueError · float("2.5") → 2.5 · str(5) → "5" · bool(0), bool("") → False.

    

    
Input

      
input() always returns a str.

      
n = int(input("n? "))
x = float(input("x? "))

    

    
Output

      
print(a, b) → space between, newline after. sep="-" between, end="" after. \n newline, \t tab.

      
f"{name} is {age}", f"{x:.2f}" → 2 decimals, rounded.

    

    
Conditions

      
A condition is a boolean expression: < <= == >= > != give a bool. == compares, = assigns. and both, or either, not flips. Ranges: a >= 3 and a <= 5.

    

    
if / elif / else


if c1:
    ...
elif c2:
    ...
else:
    ...

      
Colon, indent. First true branch only; specific tests first.

    

    
Functions


def name(p1, p2):
    """Purpose, params, returns."""
    ...
    return a, b

x, y = name(arg1, arg2)

      
Define before calling. Parameters and inner variables are local. No return → None.

    

    
Built-ins

      
print input int float str bool type len max min abs round help. import random; random.randint(a, b) includes both ends.

    

    
Errors

      
SyntaxError (missing :, = for ==, bad name) · IndentationError · NameError (typo, case, undefined) · TypeError (int + str, wrong number of arguments) · ValueError (int("abc")).

      
Syntax errors stop the file before it starts; runtime errors stop it at the bad line; logic errors give a wrong answer and only testing finds them.
